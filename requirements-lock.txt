# handsoff - resolved dependency closure (constraints, not a requirements set)
# closure: 41 packages (7 direct, 34 transitive)
#
# WHAT THIS IS. Every distribution reachable from requirements.txt, pinned to
# the version a fresh resolve selects - 41 packages, not the 7 direct ones.
# The earlier file named the direct dependencies only, so ~34 transitive
# packages (tokenizers, ctranslate2, scipy, scikit-learn, huggingface-hub,
# av, ...) floated freely on a machine that installs a 3.8 GB neural speech
# model and holds the microphone, the desktop and the filesystem.
#
# MEASURED, NOT ASSUMED. Resolved for each matrix leg with
#   pip download --only-binary=:all: --python-version <3.12|3.13|3.14> \
#       -r requirements.txt -c requirements-lock.txt
# and all three returned the IDENTICAL set below - so one lock serves every
# leg and no environment markers are needed. Regenerate the same way after
# touching requirements.txt, and expect the closure size to move.
#
# NO HASHES, DELIBERATELY. A hash-pinned closure is per-platform: these wheels
# are manylinux x86_64, and `--require-hashes` refuses every other machine
# rather than degrade. This is a desktop app that people run on whatever they
# own, so a lock that only works on one architecture is a worse failure than
# a lock that pins versions. Integrity stays where it can be exact and
# platform-independent instead: CI images are pinned by digest and the
# speech weights are SHA256-verified before use (see install.sh).
#
# NOT "WHATEVER A FRESH RESOLVE PICKS" (2026-09-28). "The version a fresh
# resolve selects" is the wrong target for this lock, and it was wrong in a way
# that only showed up on somebody's machine. install.sh installs with
# `--user --break-system-packages` into a site-packages that ALSO holds the
# user's own tools, so a pin here is not a statement about handsoff — it is a
# statement about every other program on the box. Resolving newest-first picked
# filelock 4.0.3, tokenizers 0.23.2 and fsspec 2026.9.0, all three inside
# handsoff's own ranges (huggingface-hub wants filelock>=3.10, fsspec>=2023.5.0;
# faster-whisper wants tokenizers<1,>=0.13) and all three BREAKING a neighbour:
# virtualenv 21.x needs filelock<4, transformers 5.x needs tokenizers<=0.23.0,
# datasets 4.x needs fsspec<=2025.9.0. pip printed the conflict and installed
# anyway, and the app was fine, so nothing looked wrong until the user noticed
# their other tools were unhappy.
#
# So three pins sit BELOW the newest the resolver offers, at the top of the
# range both sides accept. The intersection, measured 2026-09-28:
#   filelock    handsoff >=3.10.0        x virtualenv >=3.24.2,<4   -> 3.32.7
#   tokenizers  handsoff <1,>=0.13       x transformers >=0.22.0,<=0.23.0
#                                                                  -> 0.22.2
#   fsspec      handsoff >=2023.5.0      x datasets >=2023.1.0,<=2025.9.0
#                                                                  -> 2025.9.0
# REGENERATING? Re-read this section first. A plain
# `pip download -r requirements.txt` puts these three back to newest and
# re-breaks the neighbours, silently, because nothing in handsoff fails.
#
# CAVEAT, still true: install.sh step [2b/8] installs chatterbox-tts with NO
# constraints file, so it re-resolves that engine's closure afterwards and can
# still move these. It is the step that actually decides the final versions.
#

# existed can hold older versions; re-sync with
#   pip install --user -r requirements.txt -c requirements-lock.txt
